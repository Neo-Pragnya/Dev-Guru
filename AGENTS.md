# Working in Dev Guru

Instructions for coding assistants and contributors. Read these before changing code.

## Boundaries (non-negotiable)

- **Ananke owns domain compute.** Parsing, graphs, scanners, tool and model invocation, workflow execution, policy,
  run state and evidence live in Ananke Plexus. Dev Guru calls them through `dev_guru.client` and never
  re-implements them.
- **Dev Guru owns presentation.** Rendering, report view models, product UX, SDK and CLI, preferences, saved views
  and, later, the local gateway and web UI.
- **Dex Trove is optional.** Never import `dex_trove` in the core (tests/test_packaging.py enforces this). Use it
  only behind the optional `dex` extra, through Ananke's source port.
- **One transport per run.** `connect(transport)` returns exactly that transport. A failing transport is an error;
  never retry silently on another one.
- **No Node at runtime.** Reports are generated by Python. A later UI ships precompiled assets.
- Ananke must never import Dev Guru. Dev Guru renderers join Ananke workflows as generic artifact producers.

## Work discipline

- The active queue is `Planning/unified-backlog.json` in the design bundle
  (`Ideation/Ananke-DexTrove-DevAcharya/Dev_Guru_Three_Repo_Implementation`). Keep task ids (I01–I41, ADV01–ADV18, the
  163 inherited ids).
- Inspect real interfaces before writing code against them. The Ananke facade is `ananke.plexus.api.Ananke`; the
  audit is `docs/reference/three-repository-audit.md` in Ananke Plexus.
- Each task ships code, meaningful tests, docs and a short evidence note. Track *proposed*, *implemented*,
  *verified* and *released* separately. Mocks test the port, but only a run against the real harness proves
  integration.
- Errors use the stable codes in `dev_guru.errors`. Add a code there before using it.

## Commands

```bash
make install            # uv sync --all-extras
make verify             # lint, format check, mypy --strict, tests
make acceptance         # capability scenarios (dev install)
make acceptance-wheel   # the same against the built wheel (what ships)
make scan               # distribution scan of dist/
uv run devguru doctor   # harness check
```

`acceptance/harness.py` and `scripts/scan_dist.py` are byte-identical copies from Ananke Plexus. Change them there.
